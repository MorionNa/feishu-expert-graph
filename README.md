# 飞书专家关系图谱

只读的飞书多维表格关系网络组件，基于「专家信息表」「身份和履历表」「人员关系表」。

## 安全原则

- 本公开仓库只包含源代码和 **完全虚构** 的演示数据，绝不保存真实专家资料、表格导出、联系人信息、飞书密钥或访问令牌。
- GitHub Pages **公开可访问**。直接访问网页不会读取飞书数据；只有在飞书应用里、通过飞书 SDK 成功读取时才展示授权数据。
- **飞书应用权限独立于源表权限。** 必须配置应用的阅读者权限，并通过无权限账户实测。公开前端本身不构成完整的安全隔离。
- 插件目前不写入数据、不持久化缓存、不向第三方提交数据。严禁在浏览器控制台或 GitHub Issues 贴出真实数据。
- 对特别敏感的人员关系，建议正式阶段启用服务端鉴权或内部托管，不要仅依靠静态插件的“在飞书中打开”判断。

## 快速开始

1. 打开仓库 **Actions**，确认 Deploy GitHub Pages 构建成功；到 **Settings → Pages → Build and deployment** 将 Source 设置为 **GitHub Actions**（若尚未设置）。
2. 浏览器打开 https://morionna.github.io/feishu-expert-graph/?demo=1 查看 **虚构三人图谱**。此页面不连接飞书。
3. 在飞书多维表格应用模式 → 添加组件 → 插件 → 更多 → 添加自定义插件，服务地址填写 https://morionna.github.io/feishu-expert-graph/ 。
4. 保存插件为应用页面的一个组件后，打开应用页面将自动读取下面三张表；「刷新数据」按钮用于手动更新；字段名称不同可在「数据设置」内修改表名。
5. 在「最短路径」选择起点与终点，查看高亮路径；点击节点查看专家信息，点击线查看关系信息。

## 与现有三张表的映射

- **专家信息表**：人员ID、姓名、当前身份与任职、研究或业务领域。
- **身份和履历表**（非必需字段允许为空）：关联人员、身份、任职状态、添加时间、结束日期。
- **人员关系表**：关系ID、人员A、人员B、关系类型、关系方向、最后确认日期（可选）、备注。

表名兼容「专家」「身份与履历」「人员关系」等常见名称。关联字段必须真正使用飞书 **单向/双向关联**；程序按飞书记录 ID 匹配人员，而非按重名的姓名匹配。**只要人员关系表有一条可正常解析、并且两端指向不同专家的关系记录，就直接显示连线并参与路径计算。** 不依赖核验状态。删除关系记录后，再打开页面或点击「刷新数据」会移除对应连线。

## 技术实现

- Vite + @lark-base-open/js-sdk + Cytoscape.js
- SDK 在飞书嵌入环境内读取当前表格，无需 App Secret。
- 数据只驻留当前页面内存；关闭页面后不保留。
- 支持 200 条/页分页读取；有错误就显示错误，不悄悄用演示数据冒充真实结果。
- 测试：npm test；构建：npm run build。

> 注意：**飞书应用模式**的自定义插件宿主 API 可能与传统侧边插件有差异，当前仓库的飞书数据连接在真实应用宿主内仍需验收。若提示无法读取，请通过飞书插件市场的「开发资源」核对宿主 SDK，并反馈不含个人信息的报错。
## 飞书应用中保存为固定页面

1. 打开多维表格应用模式的 **编辑** 界面，使用左侧「新建」创建页面并命名为「专家关系图谱」。
2. 在此页面点「添加组件」→「插件」→「更多」→「添加自定义插件」，输入无 `?demo=1` 参数的服务地址。
3. **添加成功后返回页面画布**，确认「未命名插件」作为组件出现在该页面里，而不是只停留在插件弹出预览窗口。按需调整组件尺寸。
4. 顶部确认「已经保存到云端」，然后点击「完成编辑」。再次进入该应用，在左侧点击「专家关系图谱」，即可加载该组件，嵌入时会自动读取。点击「刷新数据」只作为备用。
5. 如果应用左侧没有图谱页面，或退出预览后画布仍为空，请重新选择添加插件的动作，并核对应用角色权限。不要把公开的 GitHub Pages 网址作为飞书应用外部分享入口。

## 飞书仪表盘创建模式（关键）

使用飞书「应用模式 → 页面 → 添加组件 → 插件 → 添加自定义插件」输入网址，首次启动时页面会显示 **「保存并添加到页面」** 按钮。该按钮通过官方 `bitable.dashboard.saveConfig({dataConditions: [],customConfig:{...}})` 完成持久化。只有完成保存，关闭弹窗后组件才会出现在飞书页面画布中；直接打开网页/关闭弹窗并不等同于添加成功。

保存后点击应用右上角「完成编辑」。下次进入飞书应用对应页面，插件会自动读取三张表，不需要每次点击「刷新数据」。如果未出现保存按钮或保存报错，请截取不含专家隐私资料的错误提示，核查 SDK 的 DashboardState 环境及插件宿主权限。

## 展示模式接口限制与修复

飞书应用页面的仪表盘展示模式可能不允许 `bitable.base.getTableMetaList()` / `getRecordsByPage()`；遇到 `this api is only supported in config mode` 时不能只重试。当前实现优先通过配置时保存的 `baseToken` 使用 `workspace.getBitable(baseToken)` 的授权接口读取原始记录；旧组件尚未绑定 token 时仅检索已授权工作区的**表名元数据**并要求唯一匹配。多库重名或权限不足时明确报错，不静默读取其他专家库。

如果依然不支持，下一步需要改用飞书开放平台的后端授权接口（密钥只放服务端，绝不能放进 GitHub Pages）。该展示态读取方式需在实际飞书宿主验证。

## 展示模式故障排查（2026-10）

如果保存后报 `this api is only supported in config mode`，说明视图模式调用到了仅配置态可用的 API。最新实现不会在展示态枚举工作区；需在飞书应用的组件编辑配置里通过「数据设置」填入该专家库多维表格 URL 中 `/base/` 后的 Base 标识，再点击「保存并添加到页面」。组件只保存 Base 标识（不是访问密钥）。之后展示态先尝试 `workspace.getBitable(baseToken)` 读取授权数据。**该能力是否受当前飞书租户/应用模式权限支持，仍须在真实展示态验证**；如果 `workspace.getBitable` 同样被限制，就需要改为受鉴权保护的服务端飞书 OpenAPI 接口，不能通过静态 GitHub Pages 端暴露令牌。不要将个人信息写入公开仓库。

## 2026-10-18 展示模式表结构兼容修复

现有保存版图谱之前报 `读取数据表元信息失败: this api is only supported in config mode`，原因是 View 态调用 `getTableMetaList/getFieldMetaList`。现在在 Create/Config 模式执行 `captureTableBindings`，将三张表的真实 `tableId` 与字段 `fieldId/name` 保存到图谱的 `customConfig.tables.tableBindings`；展示模式不再调用这些元信息 API，而是尝试直接通过保存的 ID 读取记录。**必须回到图谱组件编辑配置重新点击「保存并添加到页面」一次**，旧配置不含 ID 映射，无法自动升级。

如果 View 态仍报 `getRecordsByPage: this api is only supported in config mode`，说明该宿主连原始记录 API 都受限，不能继续用前端 SDK 绕过权限。必须改为飞书正式授权的服务端 OpenAPI 或验证仪表盘聚合 `dashboard.getData` 能否无损传递关系信息。不要将专家库导出放在 GitHub Pages，也不要公开 access_token。
